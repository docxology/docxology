# AGENTS.md — `papers/2025_BiofirmDevelopmentWith/images/`

Figure images for [Biofirm Development with First Principles First and the Active
Inference Institute at the Applied Active Inference Symposium 2024](../README.md)
(`2025_BiofirmDevelopmentWith`). The paper's `../full_text.md` does not embed them, but
the generated work and paper pages list the folder as the paper's extracted-image set
and link it as figures held in the repository.

- The folder's provenance is not recorded in the repository. There is no archived PDF in
  `../`, the 10 files are named `image1`–`image10` rather than the `pageN_imgM` form
  that `code/orchestrators/extract_paper_texts.py` writes, and `../full_text.md` does
  not reference them. Nothing in the repository states what produced them or which pages
  of any source they depict.
- `../` does hold a presentation deck (`BIOFIBIOFIRM_v2.pptx`). This guide does not
  claim these images were rendered from it; that relationship is not recorded anywhere
  in the repository.
- The folder held 10 images (3 PNG and 7 JPEG) on 2026-11-02. Treat the directory
  listing as the current truth: this guide is not a manifest and will not be updated
  when files are added or removed.
- The generated paper page shows them as repository thumbnails rather than hosted
  copies, so the repository copy is the only one and the paper folder's own documents
  remain the authoritative account of what they show.
- There is no test, CI job, or runnable gate for this folder. The
  repository-wide check that would notice a broken link is
  `uv run python3 code/orchestrators/validate_repo.py`; it does not inspect
  image content or figure fidelity.

The paper-folder contract is in [`../../README.md`](../../README.md) and
[`../../AGENTS.md`](../../AGENTS.md).
