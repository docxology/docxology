Green Line: a capacity-under-development instrument

Daniel Ari Friedman

Zenodo

Download PDF Publication source Paper folder on GitHub Read extracted text

Overview

A capacity-under-development instrument: the green line of the docxology line-set. It records what is deliberately still being learned — apprenticeships, skills not yet mastered — with marker/counter-signal staging, and reads declared growth records against a versioned registry. Observations phrased as certification or credential language are staged aside with a note, never scored. It measures what is still growing — never competence, mastery, or virtue. Code and prose are Apache-2.0 licensed. See LICENSE in the repository.

Methods and contributions

Findings and contributions

  • A read returns one of four staged statuses describing marker coverage at a review date, explicitly not competence, mastery or permission.
  • In the worked example, one applied record reads STAGED and the rest NEEDS_MARKER, so the overall status is NEEDS_MARKER.
  • Adding a 'certified as expert' observation leaves the read unchanged because certification language is staged aside rather than scored.
  • The author states the limit that a read describes marker declarations, not verified practice or skill growth.
  • The author notes counter-signal detection is lexical, so an innocently phrased resume-shaped record passes intake.

Methods

  • Three-stage read: intake, tag-intersection matching, status projection — Self-declared observations are normalized fail-closed, matched to growth records whose tags intersect the attempt's tags, then projected into present/missing/stale marker surfaces.
  • Formal definitions of growth records, freshness windows and aggregation — Defines growth records, cultivation attempts, freshness relative to a review date and window, a finding rule, and an aggregation rule over four statuses.
  • Lexical counter-signal staging of certification/credential language — Observations labeled with certification, credential or resume language are set aside with a note and not counted toward any marker surface.
  • Canonical serialization pinned by SHA-256 digests (pure stdlib package) — Each read is a pure function of attempt, registry and review config, serialized canonically and pinned by a SHA-256 digest of reading and registry.
